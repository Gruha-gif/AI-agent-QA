# Skill «task-design»

## Purpose - Назначение

проектировать задачи для Jira по требованиям, которые уже прошли проверку качества  
skill превращает подтверждённые требования в понятные и проверяемые задачи, но не создаёт их в Jira и не меняет сами требования

## When to Use - Когда применяется

после того как агент завершил анализ требований и проверил качество результата  
если проверка не пройдена, skill не запускается  
повторно skill запускается, если требования изменились или задачи нужно переработать после замечаний

## Inputs - Входные данные

агент передаёт skill:

- проверенные требования с номерами вида REQ-001, критериями приёмки и ссылками на источник  
- границы работы - какая функциональность попадает в проектирование  
- правила проекта Jira: типы задач, обязательные поля, шаблон описания, соглашения по названиям  
- сведения о существующих задачах, если агент их получил, чтобы проверить возможные дубликаты  
- номер текущей версии требований, чтобы связать задачи с источником  
- место сохранения результата и режим работы

skill не ходит в Jira самостоятельно и не создаёт там записи  
всё, что ему нужно для работы, передаёт агент

## Procedure - Порядок работы

1. проверить входные данные и убедиться, что требования действительно прошли проверку качества  
2. сгруппировать требования в минимальные связанные задачи по результату для пользователя или системы, а не по одному предложению на задачу  
3. для каждой задачи подготовить локальный номер вида TASK-001, название, описание, цель, ссылки на требования, критерии приёмки и зависимости  
4. формулировать критерии приёмки так, чтобы их можно было проверить, и связывать каждый критерий с требованием  
5. проверить задачи по правилам проекта Jira: подходят ли типы задач и заполнены ли обязательные поля  
6. если обязательного значения нет во входных данных, записать пробел поля, а не придумывать значение  
7. проверить результат на дубликаты внутри самого результата и, если агент передал сведения о существующих задачах, на совпадения с ними  
8. перепроверить полноту, связи и проверяемость критериев  
9. сохранить результат как артефакт

## Rules - Правила

- не создавать задачи, у которых нет основания в требованиях  
- не добавлять архитектурные решения, оценку трудозатрат, исполнителей и сроки, если их нет во входных данных  
- не менять требования и не дополнять их своими правилами  
- не создавать и не удалять задачи в Jira - это делает агент в разрешённом режиме  
- не выдавать локальный номер задачи за реальный ключ Jira  
- не подставлять произвольные значения вместо отсутствующих обязательных полей  
- не заявлять, что проверка дубликатов выполнена, если агент не передал нужных данных  
- не публиковать результат без разрешения  
- не хранить в описании skill данные конкретного проекта: ключи проектов, адреса, имена людей - всё это приходит из входных данных  
- не скрывать найденные пробелы и ошибки

## Output - Результат

оформленный набор задач, сохранённый как отдельный результат работы, в нём есть:

- **список задач** - локальный номер, название, описание, цель, тип, ссылки на требования, критерии приёмки и зависимости  
- **зависимости** - какие задачи связаны между собой и в каком порядке их логично выполнять  
- **пробелы полей** - какие обязательные данные для Jira отсутствуют и что нужно уточнить  
- **проверка дубликатов** - что проверено, а что проверить не удалось и почему  
- **готовность** - можно ли передавать задачи дальше или работа заблокирована, и почему

у результата должен быть статус: черновик, проверен, заблокирован, с ошибкой или устарел

## Completion Criteria - Критерии завершения

skill выполнен, когда:

- каждое требование покрыто задачей либо обосновано, почему задача не нужна  
- каждая задача связана с требованиями и имеет понятные название и описание  
- критерии приёмки проверяемы и подтверждены требованиями  
- зависимости не ссылаются на несуществующие задачи и не образуют цикл  
- обязательные поля заполнены или их отсутствие записано как пробел  
- результат перепроверен и сохранён с корректным статусом

решение о том, можно ли переходить к следующему этапу, принимает агент после проверки качества
